# Hello World!

## Purpose

This is a README file. These files describe the state of the repository and are the first thing people see when browsing your source code. 
Each homework assignment will include a README that initially describes the assignment's requirements.

While a README can be written in any format (txt, docx, pdf), the convention on GitHub is to use Markdown (md). 
Markdown is plain text that supports things like headers, links, images, lists, etc. 
A markdown cheat sheet is available [here](https://github.com/adam-p/markdown-here/wiki/Markdown-Cheatsheet). 
If you are familiar with HTML, you can also use that in combination with markdown or by itself. 
The **Preview** feature on GitHub.com will let you view how your README will look without having to commit first.

Each homework repository will also contain an automated tester program. The requirements in the tester may be stricter 
than those stated in the book or be altered to help facilitate testing. Generally, unless specified otherwise, you are 
allowed to solve these problems however you best see fit.

## Requirements

### For this assignment you will:
1. Write a Java class `HelloWorld` in a file `HelloWorld.java` that prints `Hello World!` to the screen. Include your name in a comment. 
Future assignments will require more detailed documentation.
2. Add, commit, and push your program to GitHub.
3. Replace the contents of this `README.md` file to reflect the current state of your repo. This initial text is meant 
for you (the student) and will be irrelevant to the reader (the grader) once you add the program. The initial version 
of this README is available in your repository's history should you need to review it. 

### Other things to note:
- Repos should only include source code, documentation, and media. Do **NOT** include executable files (.class) to your repo.
- GitHub will automatically compile and test your Java program on upload. This is not a replacement for having your own IDE 
as compute time on GitHub is limited. Improper use of the tools (git, GitHub, tester, or IDE) will result in reduced credit.
- The tester utilizes assertions which are not enabled by default. To enable assertions, you need to add `-ea` or `-enableassertions` 
when running `java` from the command line or in Geany ex: `java -ea HelloWorldTest`
- It is fine if your code does not pass the tests for minor output errors such as spelling or whitespace.
It is **NOT** fine to submit code that does not compile or code that cannot be found by the tester.
Either scenario will result in your submission being considered late.
- If you receive help/information from anyone/thing other than the lectures, textbook, or Oracle Java documentation, 
you **MUST** cite them. A comment in your README or program source is sufficient for small things. Large external contributions 
require more documentation. MLA/APA/IEEE/ACM etc. is not necessary.
